# Criar a IbagTech para construir software

Este portfólio mostra a pessoa. O GitHub mostra o código. Nenhum dos dois responde, sozinho, a pergunta que um cliente faz antes de mandar a primeira mensagem: *quem constrói isso comigo?*

A **IbagTech** nasceu para ser essa resposta.

## Um nome para o trabalho, não para o currículo

Durante um tempo, cada entrega saía com a minha assinatura. Um site institucional aqui, um app ali. Funciona enquanto o trabalho é uma conversa entre duas pessoas. Para de funcionar quando o que está à venda deixa de ser “umas horas de desenvolvimento” e passa a ser um produto: prazo, escopo, design, engenharia e o que acontece depois do deploy.

Uma marca segura isso. Ela não substitui quem escreve o código. Ela organiza a promessa.

A promessa da IbagTech é direta: **sites, sistemas e apps sob medida**. Software house. Do rascunho ao ar, com design e engenharia no mesmo teto. O site público está em [ibagtech.com.br](https://ibagtech.com.br).

## O que a marca se compromete a fazer

Quatro passos, sem teatro:

1. **Descoberta.** Entender o negócio antes de abrir o Figma. Dor real, escopo e um cronograma que dá para explicar.
2. **Design.** Protótipo navegável. A pessoa vê a jornada antes de existir uma linha de produção.
3. **Engenharia.** Código que aguenta crescer, sprint visível, demo no fim da semana.
4. **Lançamento.** Nuvem, deploy e o suporte que impede o projeto de morrer no dia seguinte.

Isso vale para uma landing e vale para um sistema maior. O tamanho muda. O ciclo não.

O atendimento é remoto, para o Brasil inteiro, com a base em Mato Grosso. O canal curto é o WhatsApp. O canal que fica registrado é o [contato@ibagtech.com.br](mailto:contato@ibagtech.com.br).

## O site da marca também é um produto

Não fazia sentido anunciar uma software house com uma página genérica. O site da IbagTech foi o primeiro encargo da própria marca: identidade, tipografia, movimento, um terminal na hero, formulário de contato com proteção contra spam e SEO que descreve o serviço do jeito que uma busca (e uma IA) consegue citar.

A frase que ficou na entrada é a que eu quero sustentar: *inovar é o começo dos sonhos; cada projeto construído é uma parte da essência.* Tecnologia, design e performance no mesmo espaço digital. Sem slogan que o código não consiga cumprir.

## Software com sobrenome

Com a marca de pé, os trabalhos param de parecer peças soltas.

- O [Extract Design](https://extract.ibagtech.com.br) é um SaaS: cola uma URL, recebe um `DESIGN.md` que um agente de IA consegue seguir. Cheerio quando o site é estático, Playwright quando precisa renderizar.
- O [Studio Vértice](https://arquiteto.ibagtech.com.br) e o [Studio Suzana Loroff](https://arquiteto-two.ibagtech.com.br) são modelos de site para arquiteto. Um em Next.js, o outro em Astro. Eu mando os dois para o escritório que quer fechar o site com a IbagTech.
- Memória & Ancestralidade continua no mesmo ofício: presença digital com cara de quem vai usar, não de template.

A faculdade fica no lugar dela. O TCC ensinou geodado e crowdsourcing. A IbagTech não é um trabalho de disciplina. É a casa onde o software de cliente e o software de produto passam a ter o mesmo sobrenome.

## Por que isso importa agora

Sem marca, cada projeto novo reexplica quem eu sou. Com marca, o projeto explica o problema do cliente. Eu continuo sendo quem implementa. A IbagTech é o lugar em que isso vira oferta: descoberta, desenho, código e o dia em que sobe para produção.

O site está no ar. O restante é continuar construindo.
